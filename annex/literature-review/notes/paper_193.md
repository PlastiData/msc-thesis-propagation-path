## Problem statement

Current cloud observability solutions suffer from fundamental limitations that prevent operators from deriving actionable insights in real time. These systems are typically siloed, meaning logs, metrics, and traces are stored and analyzed separately without unified integration. The dashboard-centric approach forces operators to manually correlate information across multiple views and tools. Existing analytics capabilities are limited to surface-level correlations that do not capture deeper causal relationships or dependencies between system components. The volume of telemetry data generated by cloud platforms is vast and continuously growing, making manual analysis increasingly impractical. Operators struggle to answer critical operational questions such as understanding failure propagation paths or predicting downstream impacts of component failures. The gap between raw observability data and actionable intelligence creates delays in incident resolution and increases the cognitive burden on site reliability engineers.

## Method summary

Log2Graph introduces a framework that leverages large language models to transform heterogeneous telemetry data into dynamic knowledge graphs. The system ingests multiple types of observability data including unstructured log messages, distributed traces, metrics, and configuration information. The LLM processes this heterogeneous input to extract entities, relationships, and dependencies, constructing a unified graph representation. This knowledge graph is dynamic, meaning it continuously evolves as new telemetry data arrives and system state changes. The framework performs real-time dependency mapping by identifying service relationships and communication patterns from the integrated data sources. Causal chain analysis capabilities allow the system to trace failure propagation paths through the dependency graph. The framework supports natural language querying, enabling operators to ask questions in plain language about system behavior, dependencies, and potential failure impacts. The LLM interprets these queries and generates responses by reasoning over the knowledge graph structure, providing graph-backed explanations for its answers.

## Gaps this paper opens

The framework introduces natural language querying over dynamic knowledge graphs but does not detail how query ambiguity or complex multi-hop reasoning is handled. The relationship between the LLM-constructed graph and traditional static dependency models remains unexplored, particularly regarding validation and correction mechanisms. The paper does not address how the system handles contradictory information from different telemetry sources or resolves conflicts in dependency inference. The temporal evolution of the knowledge graph is mentioned but the mechanisms for graph versioning, historical analysis, or temporal reasoning are not specified. Integration with existing root cause analysis techniques and how the knowledge graph could enhance causal inference remains an open question. The framework focuses on observability but does not extend to automated remediation or recommendation generation based on the constructed knowledge. The role of human feedback in refining the LLM's entity and relationship extraction over time is not discussed.

## Relevance to the thesis topic

Log2Graph is highly relevant to the thesis topic as it addresses both service dependency topology and temporal analysis in cloud-native systems. The framework's dynamic knowledge graph construction directly supports dependency analysis, which is a core component of root cause analysis frameworks. The integration of heterogeneous telemetry sources including logs, traces, and metrics aligns with the observability data requirements for comprehensive RCA. The causal chain analysis capability mentioned in the framework relates to temporal failure propagation, enabling understanding of how failures cascade through dependencies. The real-time evolution of the knowledge graph addresses the temporal dimension necessary for tracking how system state and dependencies change over time. The natural language querying interface could complement RCA workflows by allowing operators to explore dependency relationships and failure scenarios interactively. However, the framework appears focused on graph construction and querying rather than automated root cause identification, suggesting it would serve as a foundational component within a broader RCA system rather than a complete solution.
